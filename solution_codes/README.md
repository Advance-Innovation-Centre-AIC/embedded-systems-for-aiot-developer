# เฉลย — ครูคนที่สองของทีม ไม่ใช่ทางลัด

โฟลเดอร์นี้มีไฟล์เฉลยของทุกคาบ จับคู่หนึ่งต่อหนึ่งกับไฟล์ฝึกใน `practise_codes/`
เช่น `practise_codes/s03_led_button.py` คู่กับ `solution_codes/s03_led_button.py`

เฉลยมีไว้ให้ **เทียบหลังจากพยายามเองแล้ว** ไม่ได้มีไว้ให้คัดลอกวาง
โค้ดที่คัดลอกมาจะรันผ่านในคาบนั้น แล้วหายไปจากหัวภายในหนึ่งสัปดาห์ — เราเคยเห็นมาหลายรุ่นแล้ว

## วิธีใช้เฉลยอย่างซื่อสัตย์ — สี่ขั้น

**ขั้นที่ 1 — ลองเองก่อนอย่างน้อย 15 นาที**
อ่านคำใบ้ `# เติม:` ในไฟล์ฝึก ลองเติมแล้วส่งขึ้นบอร์ดดูผลจริง
ถ้ามัน error ให้อ่านข้อความ error ให้จบก่อนถามใคร — ข้อความนั้นมักบอกบรรทัดที่ผิดตรง ๆ

**ขั้นที่ 2 — เปิดเฉลยอ่าน แล้วปิด**
อ่านให้เข้าใจว่าทำไมเขาเขียนแบบนั้น ไม่ใช่แค่จำว่าเขาเขียนอะไร
แล้ว **ปิดไฟล์เฉลย** ก่อนกลับไปแก้ไฟล์ของตัวเอง

**ขั้นที่ 3 — พิมพ์เอง ห้ามวาง**
กลับไปที่ไฟล์ฝึกแล้วพิมพ์ด้วยมือ ไม่ใช้ copy-paste
นิ้วที่พิมพ์เองกับตาที่คัดลอก จำคนละแบบกัน และเวลาสอบหรือทำงานจริงเรามีแค่ความจำแบบแรก

**ขั้นที่ 4 — รันแล้วลองแก้ตัวเลข**
เปลี่ยนค่าหน่วงเวลา เปลี่ยนสี เปลี่ยนช่วงของกราฟ แล้วดูว่าอะไรเปลี่ยนบนจอ
การรู้ว่า "ถ้าแก้ตรงนี้จะเกิดอะไร" คือความเข้าใจจริง ส่วนการรู้ว่า "โค้ดที่ถูกหน้าตาแบบไหน" เป็นแค่ความจำ

## เขียนใบงานด้วยคำของตัวเอง

ข้อ 5 (สังเกต + วิเคราะห์) และข้อ 6 (สะท้อนการเรียนรู้) ในใบงาน ให้เขียนจากสิ่งที่ทีมเห็นบนจอจริง
ห้ามลอกคอมเมนต์ในไฟล์เฉลยมาตอบ — ผู้สอนอ่านออกทุกครั้ง และมันทำให้เสียโอกาสได้คะแนนช่วง Verify ไป 25%

## ข้อแตกต่างระหว่างไฟล์ฝึกกับไฟล์เฉลย

| | `practise_codes/` | `solution_codes/` |
|---|---|---|
| โครงสร้าง | ครบ 70% แล้ว | เหมือนกันทุกบรรทัด |
| ช่องว่าง | มี `pass` พร้อมคำใบ้ `# เติม:` | เติมครบแล้ว |
| คอมเมนต์ | บอกว่า *ต้องทำอะไร* | อธิบายว่า *ทำไมต้องทำแบบนั้น* |

คอมเมนต์ในไฟล์เฉลยคือส่วนที่มีค่าที่สุด — อ่านคอมเมนต์ให้มากกว่าอ่านโค้ด

## ถ้าติดจริง ๆ

บอกผู้สอนว่า **"ลองอะไรไปแล้วบ้าง และเห็นผลอะไร"** ไม่ใช่แค่ "มันไม่ทำงาน"
การเล่าสองอย่างนี้ได้ คือครึ่งหนึ่งของการแก้ปัญหาแล้ว และเป็นทักษะที่ใช้ได้ตลอดชีวิตการทำงาน
