BENTO-MISRA-CT01 | 8.7, 8.9 | c-twins: the one callback-state object per file | advisory | A program built on bento_game hands its frame callback, update(void *user, bool *out_stop), a void * only (bento_game.h bento_game_update_fn). Converting it back would break Rule 11.5, and a PSoC Edge native module has no writable static data (MicroPython tools/mpy_ld.py, docs/develop/natmod.rst). So the state the callback needs is ONE non-static file-scope object with no initialiser, named g_*, declared extern just above its definition (Rule 8.4 holds), set in main(); the callback writes (void)user. This applies below the 512 bytes of the library's E03 rule, for this object only; every other file-scope object follows E03. | approved-by: pending professor review
BENTO-MISRA-CT02 | 8.7, 8.9 | c-twins: the student-settings block at the top of a file, between "/* ---- แก้ก่อนรัน: settings (MISRA deviation CT02) ---- */" and "/* ---- end of settings ---- */" | advisory | The values a learner must edit before running (Wi-Fi name and password, team, broker, device id, crop, offsets) stay in one block at the top of the file, with the same UPPER_CASE names and order as the MicroPython original, so a learner finds and edits them in one place in both languages. Each is a static const read-only object (no writable static data on the PSoC Edge); Rule 8.9 would put each inside the one function that reads it. Only those values sit in the block; every other object follows Rule 8.9. Owner decision 2026-11-03. | approved-by: Assoc. Prof. Wiroon Sriborrirux, 2026-11-03
